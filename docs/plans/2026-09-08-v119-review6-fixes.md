## Task 3: Repair the corrupted design doc's control bytes (e)

**Depends on: Task 2.**

**Files:**
- Modify: `docs/plans/2026-09-07-shared-entry-validator-hardening-design.md`

Line 25 of the file has three raw ASCII control bytes — NUL (0x00), 0x1F, 0x7F — inside
a regex code span: the byte sequence is `[` NUL `-` 0x1F 0x7F `]` where the readable
intended text is `[\x00-\x1f\x7f]`. Git flags the file binary via its NUL heuristic (the
file decodes as valid UTF-8; the em-dashes/arrows are fine). Fix by a byte-level replace
of exactly those three control bytes with their escaped text. Do NOT whole-file-rewrite,
do NOT transcribe `cat -v`'s `[^@-^_^?]` literally, and use `rb`→`wb` (an
escape-interpreting write path would re-insert the NUL).

**Step 1: Confirm the corruption (RED)**

Run:
```bash
grep -a -c -P "\x00" /Users/roberthyatt/Code/ironclaude/docs/plans/2026-09-07-shared-entry-validator-hardening-design.md
```
Expected: `1` — one line contains a raw NUL byte (the defect; git treats the file
binary). There is NO UnicodeDecodeError — the file decodes fine today.

**Step 2: Byte-level replace the control bytes**

Run (reads bytes, replaces exactly the corrupted regex span, writes bytes):
```bash
PYTHONUNBUFFERED=1 .venv/bin/python -c "p='/Users/roberthyatt/Code/ironclaude/docs/plans/2026-09-07-shared-entry-validator-hardening-design.md'; b=open(p,'rb').read(); n=b.replace(b'[\x00-\x1f\x7f]', b'[\\x00-\\x1f\\x7f]'); assert n!=b and b'\x00' not in n; open(p,'wb').write(n); print('replaced', len(b), '->', len(n))"
```
Expected: prints `replaced <M> -> <N>` (exactly one span replaced; no NUL remains). The
`b'[\x00-\x1f\x7f]'` search pattern is the raw control bytes; the `b'[\\x00-\\x1f\\x7f]'`
replacement is the literal escaped text.
