## Findings

### Critical

**C1 — worker handoff — ambiguous native-log evidence permanently suppresses ordinary worker lifecycle (completion, dead-session detection, stuck-kill) for every managed worker.**
`commander/src/ironclaude/main.py:1689-1842`, `:4823`, `:4498`; `commander/src/ironclaude/worker_quota.py:10`, `:262-263`, `:307-308`, `:446-447`, `:503-504`.

Scenario: a managed Claude or Codex worker whose native JSONL contains one line longer than 256 KiB (a large tool result). `read_native_quota` hits `len(line) > MAX_RECORD_BYTES` and returns `unknown`/`incomplete_native_record` *before* advancing the cursor (worker_quota.py:262-263: `return _result("unknown", "incomplete_native_record", reader)` precedes `reader["cursor"] = end` at :505). Every daemon cycle re-reads from the same cursor and gets the same verdict. `_native_handoff_gate` returns `True` for every `unknown` state (main.py:1815-1831 and :1836-1842 both end in `return True`), and `_check_worker_completion` does `if self._native_handoff_gate(current): continue` (main.py:4823) before the `.done`, idle-TTL, dead-session and check-in branches; `_confirm_and_kill_stuck_worker` does the same at :4498. Outcome: the worker is never completed, its dead tmux session is never noticed, it is never stuck-killed, and Brain check-ins stop — until the operator intervenes. One Slack/Brain notice fires the first time (`record_native_quota_unknown_observation`), then silence.

The same permanent-gate shape applies to `malformed_native_record`, `native_metadata_missing` (Codex `event_msg` before `session_meta`), `unsupported_codex_quota_schema`, `unrelated_codex_quota_scope` (a `premium` or `codex_bengalfox` limit reached — both `limit_id` values exist in the operator's logs), `native_turn_missing`, `invalid_native_timestamp` and `native_turn_mismatch` — each returns before the cursor advances.

Evidence that this is common, not theoretical (operator's own machine, read-only): 468 files under `~/.claude/projects/*/*.jsonl` and 267 files under `~/.codex/sessions/**/*.jsonl` contain at least one line over 262144 bytes.

Requirement violated: R8 "Keep same-provider resume and ordinary completion behavior unchanged"; R7's "treat ambiguous evidence as hold" scopes the hold to the *handoff*, not to the daemon's existing completion path. The tests lock the behaviour in (`test_worker_handoff_daemon.py::test_changed_native_log_warns_once_without_rewinding_trusted_cursor` asserts the gate is `True`), so no test can catch the regression.

**C2 — worker handoff — a paused handoff has no path back to `running`; the source worker is left `handoff_pending` with a `begun` workspace hold, and every Commander operation on it is blocked indefinitely.**
`commander/src/ironclaude/worker_handoff.py:327-388`, `:390-443`; `commander/src/ironclaude/worker_registry.py:412`, `:535`, `:575-598`; `commander/src/ironclaude/orchestrator_mcp.py:7287-7328`; `worker/mcp-servers/workspace-manager/src/handoff.ts:87-89`.

Scenario A (most common): the opposite client is not configured or is itself quarantined. `handoff()` claims the registry row and flips the worker to `handoff_pending` (worker_handoff.py:363-370 → worker_registry.py:412) and installs the workspace hold (`_begin_source_hold`, :377) *before* `_target()` (:378) discovers there is no opposite capability. The result is `_pause(..., "opposite_capability_unavailable")` (:385-387). The source process is still alive. Each cycle `retry_paused_preflight` re-validates quota (:414), re-snapshots the process tree and retries; it only ever leaves the paused state by succeeding at a handoff.

Scenario B: the source's own quota resets (Claude 5h/7d window) and the source resumes working — which is exactly what a quota-blocked worker does once the window passes. `retry_paused_preflight` → `_validate_quota(..., require_same_event=False)` → `actual.get("state") != "exhausted"` → `HandoffHold("native_quota_evidence_changed")` (:170-175, :424-425) → `resumed` is `False` → `return self._status(worker_id)` (:442). The reason is not in `safe_reasons` (:393-397), so even the retry stops. The storage-backed test asserts this terminal state as correct (`test_worker_handoff.py:547-552`: `status == "held"`, `reason == "native_quota_evidence_changed"`, worker `handoff_pending`, source pane alive, workspace phase `begun`).

Consequences while paused: the worker is absent from `get_running_workers()` (status is `handoff_pending`), so `.done`/dead-session/check-ins never run; `kill_worker`, `commit_worker`, `send_to_worker`, `recover_worker_integration`, `_finalize_and_release_worker` all raise `RuntimeError("active handoff blocks worker operation")` (orchestrator_mcp.py:7295-7297 wrapper applied at :7318-7328); `update_worker_status`, `update_task_status`, `complete_objective`, `set_worker_provider`, `set_worker_workspace` raise on an active handoff; the workspace `assertNoPendingHandoff` (handoff.ts:87-89) refuses every finalize/sync/abandon/cleanup/reap while phase ≠ `finished`, and a `begun` grant never expires there. The only write that returns a worker to `running` is `complete_worker_handoff` (worker_registry.py:598), reachable only through a fully successful handoff. There is no abort/cancel/release primitive, no operator tool, and `pause_reason` is cleared only by `resume_worker_handoff` (:535) from inside `retry_paused_preflight`. Operator recovery requires hand-editing two SQLite databases.

Requirements violated: R1 ("subject to configured/enabled opposite-client capability" — absent capability must mean *no* handoff, not an indefinitely held worker), R6 ("explicit recovery state" exists as a row but no recovery operation exists), R8 (ordinary completion changed).

### Important

**I1 — worker handoff — the five-hour Claude limit is classified as unsupported, so the feature never triggers on the most common Claude exhaustion.**
`commander/src/ironclaude/worker_quota.py:17`, `:60-67`, `:478-502`.

`CLAUDE_RATE_LIMIT_TYPES = frozenset({"seven_day"})`. A real record from the operator's logs (Claude Code 2.1.270) carries `"quotaLimits":{"status":"rejected","resetsAt":1789277400,"unifiedRateLimitFallbackAvailable":false,"rateLimitType":"five_hour","overageStatus":"rejected",...,"isUsingOverage":false},"error":"rate_limit","isApiErrorMessage":true,"apiErrorStatus":429` — every predicate in `_claude_quota` passes except the type set, so it returns `None`; `_claude_native_api_error` is true, so the record is treated as a generic API error and `latest_state = "unknown"` (:502). Of the 27 `quotaLimits` records on this machine, 11 are `five_hour`. The design text ("known nonempty rateLimitType/reset") does not restrict to `seven_day`. The worker sits blocked for up to five hours with no handoff, while C1 suppresses its lifecycle. Requirement: R1/R7.

**I2 — worker handoff — process-identity leases live only in the per-call `NativeProcessAdapter`, so any Commander restart (or any new controller instance) between `target_ready` and `owner_transferred` pauses the handoff non-retryably and kills the bootstrap.**
`commander/src/ironclaude/worker_handoff_process.py:25-26`, `:49-53`, `:98-112`, `:279-293`; `commander/src/ironclaude/worker_handoff.py:84`, `:777-782`, `:543-563`; `commander/src/ironclaude/orchestrator_mcp.py:854-866`.

`_readonly_leases`/`_source_identities` are instance attributes populated by `snapshot()`. `WorkerHandoffController(self)` is constructed fresh for every `handoff_worker`/`reconcile_worker_handoff`/`retry_worker_handoff_preflight` call (orchestrator_mcp.py:854-866), each with a new adapter (worker_handoff.py:84). After a restart at phase `pm_prepared`, `_transfer_owner` calls `assert_quiescent(path, allowed_pids=bootstrap pids)` (:780-782) with `_source_lease=False`; `_readonly_identity_is_live` finds no lease and returns `False`, so `assert_quiescent` raises `ProcessProofError("allowed bootstrap process lacks readonly native ownership proof")` (:111-112). That is not a `HandoffHold`, so `_reconcile_owned` maps it to `"handoff_effect_or_proof_failed"`, `_pause_after_pretransfer_failure` stops the verified bootstrap and pauses (:543-563). The reason is not retryable (`safe_reasons`, :393-397). At this point the source is already dead (`source_stopped`), PM state has already been copied to the target UUID and the design registration moved (`prepare_pm_handoff`), and the only exit is C2's. The design promised "restart reconciles recorded identity/phase". Requirements: R5/R6.

**I3 — worker handoff — a hard daemon crash during any worker's completion-loop iteration leaves an `effects_started` lease that nothing can reconcile; all later daemon lifecycle and Brain operations on that worker fail.**
`commander/src/ironclaude/main.py:4826-4830`, `:5124`; `commander/src/ironclaude/worker_registry.py:227-253`, `:255-274`, `:311-337`.

Every slow-lane cycle (15 s), for every running managed worker, the daemon does `acquire_worker_operation` then immediately `mark_worker_operation_effects_started` (main.py:4826-4830) before the body (capture_pane, stage read, finalize). `_reconcile_dead_claimed_operation` removes only rows in phase `claimed` (worker_registry.py:262-265); an `effects_started` row with a dead owner makes every later `acquire_worker_operation` raise `RuntimeError("unreconciled worker operation blocks handoff")` (:263-265 via :243-246), and `claim_worker_operation_recovery_warning` only posts a warning once (:311-337). No startup sweep touches `worker_operations` (only :4826/:5124 reference it in main.py) and no operator tool clears a lease. Graceful `cli stop` is safe (SIGTERM → `shutdown()` sets `_running=False`, loop finishes the cycle), but SIGKILL, OOM, a supervisor kill (the respawner path exists at main.py:5964) or power loss during the window freezes that worker's lifecycle — kill, commit, completion and recovery all blocked — until manual SQL. Requirement: R8 (ordinary completion unchanged) and the design's own "explicit blocker" must have a recovery operation.

**I4 — worker handoff — usage quarantine of a client has no implemented clearing path once that client's last worker has been handed off; `operator_authorized` recovery exists only as a dead parameter.**
`commander/src/ironclaude/provider_state.py:107-121`, `:143-160`, `:330-336`, `:414-467`; `commander/src/ironclaude/main.py:1844-1859`; `commander/src/ironclaude/worker_handoff.py:211-237`.

`_quarantine_validated_source` marks `(host, client, "worker", WORKER_USAGE_ACCOUNT_TIER)` unavailable with `category="usage"`; `is_available` now consults that account row for every worker tier (:107-121), so `router.resolve` (provider_router.py:77) excludes the client for all future worker spawns. `record_capability` preserves usage rows (:143-160) and `mark_available` skips them (:330-336). The only caller of `recover_usage_quarantine` is `_native_handoff_gate`'s `available` branch (main.py:1851), which runs only for a *running* worker of that client whose observed model matches. After the Claude worker is handed off to Codex there is no running Claude worker, none can be spawned, so the quarantine is permanent for the host; `operator_authorized=True` is never passed anywhere in `commander/src`. The design's "explicit operator recovery clears it" is not implemented. Requirement: R1 ("do not change … unrelated workers"), R7.

**I5 — worker handoff — cross-process lease collision makes Brain-initiated worker operations fail intermittently with a misleading error.**
`commander/src/ironclaude/orchestrator_mcp.py:7287-7328`, `:8205`; `commander/src/ironclaude/worker_registry.py:22`, `:227-253`; `commander/src/ironclaude/main.py:4826-5124`.

The Brain's orchestrator MCP server is a separate stdio process (`main()` at orchestrator_mcp.py:8205) with its own `WorkerRegistry` and `_owner_token` (worker_registry.py:22). `send_to_worker`, `send_keys_to_worker`, `approve_plan`, `reject_plan`, `kill_worker`, `commit_worker`, `recover_worker_integration` are now wrapped by `_hold_worker_operation`, which acquires the same `worker_mutation` lease the daemon holds for the duration of each worker's completion-loop body. A different owner token cannot nest, so a Brain call that lands inside the daemon's window gets `RuntimeError("unreconciled worker operation blocks handoff")` — wrong text for a routine collision, and previously these calls never failed for this reason. The window includes `capture_pane`, `_get_worker_workflow_stage`, and (on `.done`/dead session) a full finalize. Requirement: R8.

## Checklist coverage

**R4 process-stop safety.** Read `NativeProcessAdapter` fully. Targeting is per-PID with `create_time` equality (`_same_process`, :231-240); `_assert_snapshot_identities_current` refuses a reused PID before any signal; `_assert_tree_unchanged` refuses when a child appeared after the snapshot; controller/ancestor/tmux-server/`codex app` roots are refused; remote hosts always refuse (`_remote_guard` raises unconditionally for any `ssh_host`, :151-162). Signals go only to snapshotted processes, children first, SIGTERM then SIGKILL after 150 ms. A process reparented away from the pane (nohup/setsid) is only caught if `cwd`/open files/cmdline mention the worktree (`_associated`, :295-305). No way to kill a non-snapshotted process was found. Weakness is on the *proof* side, not the kill side: the quiescence proof's lease bookkeeping is in-memory (I2). The stub `_Proc.send_signal` marks the process gone immediately, so the SIGKILL escalation and wait loops have no test.

**R5 ownership CAS / rebinding / fail-closed.** `transferHandoff` (handoff.ts:71-82) is a single `BEGIN IMMEDIATE` transaction whose `UPDATE assignments` predicate includes owner, repo identity, worker, path, branch, base, HEAD, target and `active`; the handoff row's `target_owner_session_id` must already equal the input (set only by `authorize_target`, Python, in phase `begun` with `target IS NULL`). `beginHandoff` requires no `workspace_mutations` row and an unexpired grant; `assertEvidence` re-checks canonical path/branch, live HEAD via git, rebase dirs, primary ownership and integration locks. Ordinary `bind` is untouched and the test proves a stale owner still fails. Double successor launch is excluded by the registry's partial unique index on `(worker_id) WHERE completed_at IS NULL`, the `reconcile_owner` nonce+PID+create_time lease, and `tmux.has_session` refusals in `bootstrap`/`resume`. Crash recovery works for `claimed`, `source_stopped`, `owner_transferred`, `runtime_registered` phases by intent readback; it does not work for `target_ready`/`pm_prepared` (I2) and never reverses a pause (C2). Lost-update between Commander DB and workspace DB is handled by intent-before-effect records.

**R7 quota-evidence false triggers and ping-pong.** The Claude predicate requires a synthetic assistant record with `isApiErrorMessage`, `apiErrorStatus=429`, `quotaLimits.status=rejected`, integer `resetsAt`, no fallback/overage — quoted prose cannot match; identity (`session_id`, `sessionId`, `cwd`) is enforced; a later success record supersedes. Recovery requires a fresh bound turn with real output and clean completion. Ping-pong is prevented by the account-tier usage quarantine plus `excluded_clients` in `router.resolve` — strongly enough that it is permanent (I4). Stale-cursor replay is guarded by `last_line_hash`. False negatives dominate instead: `five_hour` (I1) and the permanent-unknown cases (C1).

## Observations (unverified)

1. `assert_quiescent` enumerates every process on the host and calls `cwd()`/`open_files()`/`cmdline()` on each (worker_handoff_process.py:113-126). On macOS `open_files()` for same-user hardened processes can raise `AccessDenied`, which becomes `ProcessProofError("current-user process … cannot be inspected")`; not measured here.
2. `_stop_source` compares a fresh snapshot to the claim-time snapshot by full dict equality (`fresh != source`, worker_handoff.py:721-724). A transient hook child alive at claim time and gone seconds later yields `source_process_changed_before_stop`, which is not retryable — same terminal state as C2.
3. The whole handoff runs synchronously inside `_check_worker_completion` (two 30 s readiness waits, a 15 s ack loop, capability probes), blocking the slow lane for other workers.
4. `prepare_pm_handoff` moves `registered_designs.terminal_session` to the target before owner transfer; a pre-transfer pause leaves the dead source PM root failing its own planning gates if an operator later resumes it manually.
5. `_dispatch` sends a four-line continuation through `tmux send-keys -- <text>` then `Enter` (tmux_manager.py:363-375); LF bytes are typed as keys. Whether Claude Code / Codex TUIs treat them as submit is not verified; existing `send_to_worker` uses the same path.
6. Codex bootstrap has no `--strict-mcp-config` equivalent; if `~/.codex/config.toml` loads IronClaude's workspace-manager, its session-start hooks may attempt `bind` with the bootstrap UUID while the source still owns the assignment. Rejection is expected but any side effect was not traced.
7. Codex `rate_limit_reached_type` is `null` in all 78,575 local observations; the exhaustion shape in `token_count.rate_limits` is asserted from fixtures only, while the `codex_error_info: usage_limit_exceeded` path matches real records.
8. `_native_handoff_gate` runs `read_native_quota` every 15 s per managed worker, scanning up to 10,000 records per call from the cached cursor; first-run cost on a long-lived session was not measured.
