## Deviations from the design (recorded at plan time; the design doc is locked)

1. **Item 3, schema list.** Every `.grade(` / `_call_local_grader(` call site in `commander/src` was enumerated. This found three inline grade/approved/feedback literals the design's grep missed (`orchestrator_mcp.py:5976`, `:6133`, `:7111`); they are included. `_GRADER_VERDICT_SCHEMA` (`orchestrator_mcp.py:901`) is **excluded**: it is never passed to `grade()`. It only feeds the Claude CLI `--json-schema` and the Codex `--output-schema` (`orchestrator_mcp.py:1195-1248`), which do not truncate at `openai.max_tokens`. Adding `maxLength` there has no truncation benefit and risks a strict-schema rejection. This follows the design's own rule, "every schema passed to `grade()`".
2. **`_PERMISSION_SEEKING_SCHEMA`** (`brain_client.py:42`) has a single boolean and no strings or arrays. It is already bounded and is left unchanged. The guard test still covers it.
3. **Testing Strategy, "`_detect_worker_prompt` passes 4096".** This is implemented as the bound on `_PROMPT_WAITING_SCHEMA.properties.interaction_block.maxLength == 4096`, which matches the validator limit at `tmux_manager.py:204`. The guard test asserts it.
4. **Item 6.** The detached plus usable origin/HEAD vitest case is a coverage-gap test for behavior that already works, so it cannot be RED against the current code. Its falsifiability comes from the sibling test at `workspace-service.test.ts:2202`: that test proves a detached primary with no usable origin/HEAD throws, so the new case fails if the reaper stops preferring a resolvable origin/HEAD.
5. **Testing Strategy, "each new test must fail against the current code."** Four added checks pass today and are kept as regression guards, not RED steps. Each is falsifiable at the end state:
   - `test_grade_openai_schema_call_keeps_larger_configured_max_tokens` and the bash line `larger configured max_tokens wins for schema request` guard the `max()` arm. Replacing `max(...)` with the bare floor fails both.
   - `test_non_terminal_outcome_neither_counts_nor_resets` guards that the new reset never fires on a non-terminal outcome. Dropping `terminal and` from the new reset fails it.
   - `test_failed_dead_session_worker_still_runs_seam` guards that `failed` stays outside the `kill_worker` terminal guard. Adding `failed` to the guard fails it.
6. **Item 1, terminal set.** `failed` is excluded from the `kill_worker` terminal guard, which covers only `completed` and `killed`. `failed` is set only by the dead-session detection in `approve_plan` / `reject_plan` / `send_to_worker` / `send_keys_to_worker` (`orchestrator_mcp.py:5841`, `:5919`, `:5940`, `:6107`), and none of those runs the seam. `get_running_workers` (`worker_registry.py:160-164`) selects only `running`, so the daemon never revisits a `failed` row. That makes `kill_worker` the only path that can integrate a failed worker's reviewed work. The duplicate completion (events 13488/13489) involved `completed` workers only. Nothing sets `killed` today; it stays in the guard because `worker_registry.py:153` treats it as terminal.
7. **Item 1, unknown worker.** `kill_worker` on an id with no registry row kills the session (preserving `test_kill_worker_idempotent_for_unknown`), then returns "no registry row; nothing to finalize". It runs no seam, logs no `worker_finished`, and makes no completion claim. Today the seam returns `{"error": "worker not found"}`, which has no `failure_phase`, so the result would read as a success.
8. **Item 3, prompt-waiting bounds.** The design's 1024/1024/64/256 caps for `question` / `authority_text` / `options[].value` / `options[].label` are raised to the validator's own limits of 2048/2048/128/512 (`tmux_manager.py:164`, `:203-205`). This follows the operator's "liberal enough length" directive: the grammar never refuses text the validator accepts. The worst-case output is about 18.5k ASCII characters, roughly 4.6–6k tokens, which stays under the 8192-token floor. Token estimates assume ASCII at about 4 characters per token. The all-CJK worst case is bounded by the 8192-character pane capture (`main.py:218` `PROMPT_CAPTURE_CHARS`) and is accepted as a residual risk.

def _unbounded(node, path="$"):
    """Paths of string nodes lacking maxLength and array nodes lacking maxItems."""
    found = []
    if not isinstance(node, dict):
        return found
    t = node.get("type")
    types = t if isinstance(t, list) else [t]
    if "string" in types and "maxLength" not in node:
        found.append(path)
    if "array" in types and "maxItems" not in node:
        found.append(path)
    for key, child in (node.get("properties") or {}).items():
        found.extend(_unbounded(child, f"{path}.{key}"))
    if "items" in node:
        found.extend(_unbounded(node["items"], f"{path}[]"))
    return found
